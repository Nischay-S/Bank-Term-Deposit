Which customers will say yes to a term deposit, and why?

BankSmart AI ranks bank customers by their estimated chance of subscribing, explains each estimate, and is open about what the numbers do and do not show. It is an end-to-end project: validated data, leakage controls, model comparison, calibration, SHAP explanations and a tested dashboard.

How to read this

  • Class weights and SMOTE (applied only inside training folds) mostly moved the default 0.5 cut-off rather than improving ranking quality; a tuned threshold can do the same.
  • Probabilities were checked for calibration, so “20%” means roughly 20% of such customers subscribe.

Why did the model say that?

SHAP shows how much each input moved the model’s score, averaged over customers. Categories such as month or contact channel are added back together.

Average influence on predictions

Association, not causation

An explanation describes how the model used an input, based on patterns in historical data. It does not show that changing a customer’s attribute would change their decision.

Month and contact channel rank high. That may reflect how campaigns were run (in waves, with some contact methods unrecorded) rather than customer traits, so treat them as clues about the data, not levers for customers.

What these numbers do not tell you

This project reports its limits openly, because they change how the results should be read.

Random split versus time order

The dataset is ordered by date. The main evaluation uses a random split, which lets the model learn from later periods. Training on the earliest 60% and testing on the latest 20% gives a harsher, more realistic picture.

Known limitations

  • Offline evaluation on one bank’s 2008 to 2010 campaigns.
  • No cost or revenue data: the recall-favouring threshold is an assumption.
  • No fairness audit yet; age and marital status are inputs.
  • Pre-call excludes call duration, which is only known after the call; the post-call model is for analysis only.

Checks that were run

  • The supplied test.csv was found to be entirely contained in the training file, so it was not used.
  • A test fails if call duration leaks into the pre-call model.
  • Automated tests cover data, preprocessing, training, prediction, explanations and every app page.
  • Retraining reproduced the same results exactly (fixed seed).

How it works

Each step is a separate, tested module, and training is kept apart from the app.

  1. ValidateCheck columns, types, categories and the target before anything else.
  2. Control leakageTwo scenarios; call duration is removed by the pre-call pipeline itself.
  3. SplitStratified 60/20/20 with a fixed seed, so the class balance is preserved.
  4. CompareCross-validate eight models, including class-weighted and SMOTE variants.
  5. Select on validationChoose model, calibration and threshold without touching the test set.
  6. Test onceScore the held-out set with bootstrap confidence intervals.
  7. ExplainSHAP with documented fallbacks and plain-language wording.
  8. ServeA seven-page Streamlit dashboard with strict input checks.

Run it yourself

The trained models are in the repository, so the dashboard runs without the dataset. Python 3.11 or newer is required (3.12 was used).

Windows (PowerShell)

git clone https://github.com/Nischay-S/Bank-Term-Deposit.git
cd Bank-Term-Deposit
py -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py

macOS or Linux

git clone https://github.com/Nischay-S/Bank-Term-Deposit.git
cd Bank-Term-Deposit
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
streamlit run app.py

Prefer no installation? Open the Colab notebook, upload the dataset when asked, and run all cells.
